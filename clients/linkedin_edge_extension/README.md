## 全天计划：每小时最多 50 条

更新扩展到 **1.6.1**，在 Edge 扩展管理页点击重新加载，再刷新领英标签页。弹窗标题应显示「领英定向职位采集 · 1.6.1」，点击「开启全天计划」。全职业预设的「开始任务」也会启动同一个全天计划。普通页面变化或手动暂停会直接从断点恢复；登录、安全验证和访问限制仍需处理后继续。开启新计划会自动导出旧结果并保留上一批备份。全天计划会关闭旧的每日定时器，避免重复运行。

1.6.1 将全天计划提升为每小时最多 50 条，并允许主按钮直接恢复普通暂停任务；仍然先持久化本页职位队列，再由后台逐个打开对应详情，并保留断点、跨周期去重和访问限制冷却。

- 范围为美国＋澳洲全职业合计，按页交替国家与职业查询，新周期轮换起始查询，不保证两国各占一半，也不表示所有职业分区都已查完。
- 初次查近 7 天，目标 1000 个有效职位；每小时最多 50 个，最快约 20 个有效运行小时完成。初次目标如供应不足会延续。
- 日常查近 24 小时，每小时最多新增 50 个，每个 24 小时周期目标最高 1200 个。错过的小时不集中补抓，电脑休眠、重复职位和有效职位不足都会导致实际数量低于目标。
- 职位 ID 跨全天计划周期去重。仅计有标题、公司、地点、完整描述、匹配职位链接、可解析且在时间窗口内的发布时间，以及页面未显示停止招聘的记录。日期缺失、页面结构无法确认、详情失败、已关闭和重复记录不占目标额度。日常新增按采集当时的发布时间验证；回溯目标持续检查近 7 天窗口。
- “有效”表示以上可核查字段通过，并不保证雇主仍在招聘。日期来自页面显示时间（包含重新发布时间），按页面精度估算；搜索筛选本身不作为日期缺失时的替代证明。已有本地数据库历史不自动导入扩展的去重账本；数据库导入仍会按职位 ID 去重。
- 每条详情停留至少 60 秒，每个搜索页至少停留 120 秒；空页和大量重复页也遵守页面停留时间。额度用完保存当前页，下个小时恢复；已完成职位不会重复打开详情。
- 普通加载超时等待 1 分钟、2 分钟后分别重试；详情连续失败后记录到导出 `failures`，不计有效数量，自动继续本页下一个职位。搜索列表连续失败则暂停，避免在页面结构变化时无效翻页。
- HTTP 429 至少冷却 6 小时；登录、验证码、访问限制和非预期页面跳转仍须手动处理并继续。不会自动绕过验证或通过新建任务跳过冷却。停止按钮会关闭全天调度和重试，继续按钮重新开启。
- 每小时额度结束、队列耗尽、周期完成时自动下载累计 JSON；导入器按职位 ID 去重。队列耗尽且不足目标会报告缺口、等待 6 小时再检查。最近 90 个完成周期的统计保存在扩展 `pacedHistory`；不会把未达标标记为成功。
- 电脑保持唤醒且 Edge 持续运行、登录有效、采集页可用，才可全天调度。浏览器重启后，运行中的全天任务保留进度并等待一小时恢复；原本人工暂停的任务不会自动恢复。更新代码不等于已经在浏览器启用此计划。

延长停留只是降低访问频率，不能解决或保证避免平台限制。LinkedIn 明确不允许未经许可的自动化采集扩展：[LinkedIn 自动化说明](https://www.linkedin.com/help/linkedin/answer/a1340567/automated-activity-on-linkedin?lang=en)。

## 首次安装

1. Edge 地址栏打开 `edge://extensions`，开启「开发人员模式」。
2. 点击「加载解压缩的扩展」，选择本目录（包含 `manifest.json` 的文件夹）。
3. 刷新已登录的领英标签页，然后点击扩展图标。
4. 选择「美国 + 澳洲 · 全职业回溯 7 天」或「美国 + 澳洲 · 全职业近 24 小时」，也可继续使用 Data/Nursing 和自定义预设，然后点击「开始新任务」。

首次安装会自动开启每天本机时间 08:00 的全职业任务，并先回溯 7 天；回溯队列完成后自动切换为近 24 小时增量。可在扩展弹窗中修改时间或关闭。单次达到访问预算后会保存剩余队列，下一次定时任务从断点继续。Edge 重启会把运行中的任务标记为暂停，点击「继续暂停任务」即可恢复；验证码、登录失效和访问限制会立即暂停，不绕过安全机制。时间使用电脑本机时区（电脑设为北京时间才是北京时间 08:00）。

内置预设：

- **美国 + 澳洲 · 全职业回溯 7 天**：25 个职业大类，使用美国/澳洲国家 geoId，并在已填写行政区 geoId 后自动加入州/领地分区。
- **美国 + 澳洲 · 全职业近 24 小时**：同一覆盖队列的每日增量方案。
- **美国 · Data 相关**：Data Analyst、BI Analyst、Data Scientist、Data Engineer、Analytics Engineer、Reporting Analyst、Machine Learning Engineer。
- **澳洲 · Nursing 相关**：通用 Nurse/Nursing，以及 Registered、Enrolled、Clinical、Practitioner、Unit Manager、Community、Mental Health、Aged Care、Critical Care、Emergency、Theatre、Perioperative、Paediatric、Educator、Assistant in Nursing 和 Midwife 等关键词。

勾选“每天自动采集”并保存后，Edge 会按本机时间运行当前覆盖方案。Edge 需要保持运行；到点时没有领英标签页，扩展会在同一个 Edge 登录资料中创建一个。每批任务结束后自动下载 JSON。

全职业方案默认每批最多 300 条、每查询最多 40 页、每条间隔 12 秒，批次结束后冷却 6 小时；接近 800 条时，如果存在真实可用的更细 geoId，会自动拆成州/领地或办公方式子分区，否则标记为 `limited`。检测到 HTTP 429、请求过多或访问频率限制时，会立即暂停并至少冷却 6 小时，期间拒绝继续。地点按 LinkedIn geoId 搜索，保留中英文原始地点，不用字符串硬过滤城市或州。结果上限、账号可见范围和验证机制仍由 LinkedIn 控制，因此这里的“完整”是可验证的账号可见覆盖，不是 LinkedIn 全站绝对全集。

## 行政区 geoId 配置

`catalog.js` 已列出美国 50 州 + DC 和澳洲 6 州 + 2 领地，但这些行政区的 `geoId` 默认为空。选择 LinkedIn 职位搜索中的州/领地后，从地址栏复制 `geoId=...`，填入对应对象的 `geoId` 字段；只有纯数字 geoId 才会进入覆盖队列。这样不会因为猜测 geoId 而把职位错误归入地区。当前已保留 Melbourne、Sydney、Austin 的已知示例 geoId。

每个查询分区会记录国家、州/领地、职业大类、SOC/ANZSCO 大类代码、关键词、办公方式、结果数量和状态。导出 JSON 的 `coverage` 与 `queries` 可直接用于覆盖率报告；`pending`、`limited`、`failed` 和 `paused` 分区不会被伪装成已完成。

## 运行与结果

- 使用当前标签页进行导航。请保持该页打开，运行期间不要改变搜索条件或导航到其他页面。
- 每条结果保存到扩展本地存储；弹窗关闭不影响采集。
- 「停止」保留进度；登录失效、验证码和限流会暂停。暂时的详情加载失败按退避时间自动重试当前职位。
- 普通白屏或页面超时会自动刷新重试；验证码、登录失效和人工安全检查仍需处理后点击「继续」。
- 「导出」随时保存 JSON 到下载目录。`detail_status=complete` 表示已核对详情职位 ID 并读到描述；失败项不会冒充成功项。
- 新任务将上一批移至 `previousRun` 本地备份；开始前建议导出，备份仅保留一批。
- 页面使用延迟渲染，因此脚本会逐条滚动加载卡片，再保存本页队列并读取对应详情。只读取职位，不点击申请、收藏或消息。
- 不自动上传到项目 API。导出含 `source/source_job_id/title/company/description/canonical_url/raw_payload` 以及覆盖队列元数据，可供后续导入。

## 验证与限制

`node --test clients/linkedin_edge_extension/*.test.cjs` 验证查询构造、队列状态、范围限制、标题过滤和预设。选择器基于 2026-09-16 实际登录版领英页面；领英更换版式可能需要更新 `content.js`。首次加载扩展后仍需真实试跑验收；单元测试不能证明浏览器端采集成功。领英会限制搜索结果数量、排序和可见性，因此“全国”代表全国地域筛选，不等于领英数据库中的绝对全集。
