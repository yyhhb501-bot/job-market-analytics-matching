# 一键采集（v2）

当前领英源码为 2.2.1，SEEK 为 2.2.0。用户已将两个来源分别调整为每天 600 条有效去重职位目标，按北京时间自然日统计；工作时间仍为 09:00–23:00，各来源每小时最多 50 次详情，至少停留 10 秒。达到目标后等待次日窗口；目标不等于受限时也保证抓满。

SEEK 2.2.0 将“上次上传回执（历史结果）”与服务端当前进度分开。今日进度使用设备身份查询当前服务、按北京时间日期核对，60秒内复用查询，含核对时间；失败或跨日缓存明确标记未知/过期，不把旧24/200当成今日，也不硬改数字伪造实时状态。此只读查询不消耗职位导入额度，不依赖源站复查结束。

复查兼容语义主内容 `[role="main"]`，页面缺失只记unknown，不能推断关闭；读取与同步有超时保护，历史复查不清空。SEEK 优先推进当天新详情，已有新详情后最多每小时检查一次原链接，仍共用每小时50次访问预算。后台定时器延迟醒来后先检查已加载的详情并保留至少10秒停留，避免直接误判超时。源码更新后仍需在Edge重载才算浏览器载入，版本与实际新增必须另行核对。

领英逐页轮流推进未完成分区，各分区保存自己的下一页；跨午夜、达到日目标或浏览器重启后继续同一队列，不再每天从头重建。全部分区处理过后才进入下一轮，最近30轮分区状态报告保存在本地；失败、达到页数上限均不计为完整采集成功。升级保留旧200任务的职位、页码、手动暂停、重试与小时账本。后台标签页定时器延迟唤醒时，先检查已渲染正文再判断超时，仍须满足安全检查、日期、完整度和停留要求。

目标是尽量一周遍历当前全部分区，不承诺一周采全所有职位。每天600对应每来源每周4200条目标，而每小时50次、每天14小时对应最多4900次详情访问/周，且复查、失败和无效职位也会消耗访问预算。分区会按查询结果继续细分，网站结果也持续变化；应以分区报告与真实回执为准。

2.1.1 修复普通页面加载失败的无限重试：超过配置次数后保存失败职位和原因，继续本页剩余队列；搜索分区失败则保留报告并细分或继续其他分区，无剩余任务时明确暂停。升级时恢复已经超过上限的自动重试，不解除手动暂停、安全验证、登录或限流冷却。详情支持新版正文定位，单张无法读取的搜索卡片也会保留诊断。

原链接复查结果在入库服务断开时保存并退避同步，服务恢复后重试，不再因为状态同步失败阻塞整个采集队列。若网站或接口无法打开，先运行“启动采集”恢复本机服务，再在控制台查看实际连接与入库回执。

领英按已验证采集的去重 ID 账本计算今日有效数，累计历史记录、旧任务有效数与今日数分开；旧任务升级保留页码、职位、手动暂停、小时访问账本。SEEK 服务端每日入库目标 200，配额只统计本来源，不再把同设备的领英导入计入 SEEK；计数与网页进度统一北京时间午夜。

领英支持旧版搜索页与新版 search-results 卡片及分页；保留查询关键词、地点、时间、办公方式与页码校验。新版页面删除排序参数时记录 site-default，不宣称仍按最新发布排序。旧版地址误判导致的 failed 检查点可在手动继续时迁移一次，保留原失败原因、历史职位和队列。其他普通失败分区在继续时自动细分；无可用细分时保留错误、转到其他待处理分区，全部处理完才要求检查覆盖报告。验证、登录、限流和冷却不能用跳分区绕过。

领英状态读取不再等待后台原链接复查；控制台启动/恢复先确认已调度，再由闹钟执行复查，避免已开始却被误报断开。

连接排查：先允许两个扩展在当前 localhost 网站运行再刷新。2.0.1 内容桥会在根节点写入无密钥版本标记，控制台区分“未注入本页”与“后台未响应”；弹窗读取浏览器实际载入版本，不使用固定版本文字。

## 首次升级一次
1. 保留原来两个扩展，分别重新加载 `clients/linkedin_edge_extension` 与 `clients/seek_edge_extension`。不要删除再安装，否则 Edge 内已有记录不能保留。
2. 批准扩展访问本机网站的新增权限，刷新控制台与两个来源页面。扩展管理页和权限确认需要用户本人操作。
3. 双击根目录 `启动采集.cmd`，等待网站与入库服务就绪。登录本地管理员账号。
4. 在 `http://localhost:3000/admin/imports` 的采集控制台点击“一键开始采集”。控制台自动连接设备并向两个扩展发送启动指令，无需复制令牌或反复导出。

## 日常使用
- 双击“启动采集”，在网站点击“一键开始”。电脑与 Edge 需要保持运行。
- **采集控制台（/admin/imports）**：
  - 页面顶部提供集中控制台，具备“一键开始采集”、“全部暂停”和 8 秒自动状态轮询。
  - “一键开始采集”独立尝试启动领英（美国全职业 + 澳洲 RN）与 SEEK（澳洲 RN），单一扩展未就绪不会阻断另一来源。
  - 两个来源卡片展示真实连接状态（运行中、等待中、重试中、已暂停、未连接），离线时明确提示重新加载扩展，绝不显示虚假零值或假装运行。
  - 分离展示“本地已采”、“待同步”与“已入库确认”（领英以服务器 ACK 确认为准）。
  - 下次执行时间均以北京时间（Asia/Shanghai）明确展示；正常等待不视为错误。
  - 若遇验证码、登录失效或访问限制，状态卡片高亮警告，必须由人工在浏览器处理后明确点击“验证后继续”。
  - 扩展弹窗（Popup）顶部提供“打开采集控制台”快捷入口，并展示精简状态摘要与同步计数；同时保留兼容的高级设置与原有参数配置。
- 正常间隔、非工作时段和小时限额会等待；页面临时故障会重试；误关或离开 SEEK 采集标签时自动新建专用采集页。
- LinkedIn 直接同步到私有入库接口；此前仍保留在当前任务中的记录在首次连接后一起同步。手动 JSON 导出用于备份。
- “待同步”表示服务器尚未确认；只有服务端明确返回接收结果才计为“已同步”。网络失败保留数据并退避重试，SEEK 不会因上传失败重新读同一详情。
- 手动暂停不会自动解除；验证码、登录失效、访问限制需处理后明确继续，429 冷却不跳过。
- 数据拒绝保留原始记录供排查，不把拒绝算成成功入库。

## 服务与数据
启动脚本沿用 `jobseek` Compose 项目和原数据卷，仅恢复 PostgreSQL、Redis、API、网站和旧版下载监听兼容服务。不启动全来源爬虫。PostgreSQL/Redis 绑定本机 15432/16379，避免与其他项目冲突；网站 3000、API 8010。

本机网站消息桥只接受顶层 localhost:3000 或 127.0.0.1:3000 的 `/admin/imports` 页面。配置须经过管理员登录和同源检查；管理员 API Key 留在服务器，设备令牌保存在各扩展本地，不展示到 DOM 或日志。

源码与本地 SQLite 升级前备份位于 `.agent/backups`。服务端原数据库卷保留；源码改完并不代表浏览器已经加载新版。实际升级后须在 Edge 验证两个扩展连接与真实入库回执。
